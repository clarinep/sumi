# Sumi documentation

Sumi is an HTTP microservice written in Rust. It renders card drop images for Blair. When a player receives a card drop in Blair, Sumi combines two card images side by side. It then stamps custom print numbers onto each card and encodes the final canvas into a WebP image.

Sumi operates as a standalone service. It includes an in-memory image cache, task queue management, and custom font rasterization.

## Core features

* **High throughput rendering:** Sumi processes image composition and text placement in parallel across available CPU cores.
* **In-memory image cache:** Sumi loads and decodes WebP card images at startup. It serves requests from memory using a concurrent map (`DashMap`) and a fast hashing algorithm (`aHash`).
* **Resource limits:** A semaphore limits concurrent rendering tasks to the number of physical CPU cores. This prevents context switching overhead and memory exhaustion.
* **Queue protection:** Sumi uses a cooperative timeout mechanism. It drops requests that wait in the task queue for more than 5 seconds and returns a 429 status code.
* **Memory pooling:** Sumi reuses canvas allocation buffers through an internal thread pool (`DROP_POOL`). This reduces heap allocation overhead during peak traffic.
* **Custom font engine:** Sumi rasterizes text using the `fontdue` library. It applies a 1-pixel drop shadow to keep print numbers readable on any card background.
